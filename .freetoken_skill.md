## 1. CRITICAL: bash tool is BROKEN

The `bash` tool in this DSH harness returns `File not found` for **any** command, including:
- `echo hello` → `File not found:`
- `cmd /c echo hello` → `File not found:`
- `pyinstaller --version` → `File not found:`
- Empty string → `command must be a non-empty string` (different error)

**Subagents inherit this bug.** `subagent`, `subagent_fork`, and `workflow` agents all
fail to run any shell command. They will say so explicitly ("the bash tool is uniformly
failing with a binding-level 'File not found' error") or refuse with safety-style prose.

### Workaround: Node.js `child_process` via dynamic import

Inside `run_code`, `await import('node:child_process')` exposes working `execFileSync` /
`spawn`. This is the only reliable way to run external programs.

```javascript
const cp = await import('node:child_process');
const { execFileSync } = cp;

const out = execFileSync(
  'C:/Users/Administrator/AppData/Local/freeToken/venv/Scripts/pyinstaller.exe',
  ['--clean', '--noconfirm', 'FreeTokenDbg.spec'],
  { cwd: 'E:/FreeToken', encoding: 'utf-8', timeout: 600000, maxBuffer: 100*1024*1024 }
);
```

This is how the last successful FreeToken.exe build was produced.

## 11. Python f-string gotcha (CAUGHT 2026-XX-XX)

Python f-string parser FORBIDS backslash escapes inside {...} expressions. The following raises SyntaxError at import time:

WRONG:  logger.info(f"x={getattr(obj, \\"name\\", None)}")
RIGHT:  name = getattr(obj, "name", None); logger.info(f"x={name}")
ALSO:   logger.info("x=%s", getattr(obj, "name", None))

This bit me at engine.py:1290 when adding the FWD ENTRY log. The engine failed to import, daemon logged SyntaxError: unexpected character after line continuation character, serve died on startup.
